# Formula Analysis Lab — 開発・テスト版 0.2

現行版とは別の試作です。現行リポジトリ `jitianduhong36-hub/formula-ev-fta` と公開URLは変更しません。

## 今回試せること
- ホーム：実際のFTAモデルから事象数、基本事象数、部品数、トップ確率を表示
- ハンバーガーメニューと画面切替：ホーム / FTA / FMEA / 部品一覧 / 今後の機能 / 保存 / 使い方
- FTA：既存の編集、図の検索移動、グループ強調、確率・最小カットセット・重要度
- FMEA：既存の下書き生成・採点・手入力・CSV/Excel出力
- 部品一覧：FMEAと同じデータを使い、基本事象へ移動。登録・編集は共通ダイアログを使用
- 全体検索：現在のシートの事象・部品を検索。Ctrl/Cmd+K、Escで閉じる
- 現行形式のJSON読込・保存。画面移動時は同じDOMを保持し、入力を消さない

## データと環境の分離
この版は**端末内保存のみ**です。共同編集・Drive連携は停止しています。
保存キーは `formula-ev-fta-dev-v1` / `fta-dev-local:{uuid}` / `fta-dev-sheet-bookmarks`。
現行のローカル保存キーは読み書きしません。クラウドURL・キーは設定していません。
`connect-src 'none'` により、ブラウザーからのfetch等の接続も禁止します。
現行の共有リンクを開発版に付けても接続しません。解析を試すにはJSONを保存し、この版で読み込んでください。
JSONの読込は開発版のコピーを編集する操作で、現行データには反映されません。
端末内保存はブラウザーごとのため、必要な結果はJSONでバックアップしてください。

## CSV・Excel・過去FMEAの追加取り込み
「インポート」→ファイル選択→シート・見出し行・列を確認→プレビュー→追加。
CSV / TSV / TXT（UTF-8・Shift_JIS）、XLSX / XLS / XLSM / XLSB / ODS、部品JSONに対応。
Excel読込は公式配布から同梱したSheetJS CE 0.20.3を専用Workerで実行。外部送信せず、マクロや数式を実行しない。数式は保存済みセル値のみ。10MiB、1050行・80列、50シート、Worker12秒の制限。データ取り込みは1回1000行。モデル全体2MiB、登録部品500件、独立FMEA2000行の制限も検査する。上限時は取り込まずエラー表示し、切り捨て保存しない。
部品ID列を指定した場合は同一IDでまとめる。IDなしは各行に新規IDを採番し、似た名前で統合しない。既存IDの更新は明示チェックを必要とし、空欄では既存値を消さない。対応する基本事象は内部IDまたは表示IDの完全一致だけを使用し、未知・曖昧なIDはエラー。複数行の対応IDは追加統合する。結合セル相当の空欄補完は明示チェックで部品ID・名称のみを前行から補う。
独立FMEA記録は `fmea.importedRows` に保存し、FTA自動生成行とは分離する。元ファイル名・シート・行番号を残し、FMEA画面下部から編集・全件CSV保存できる。D空欄は保持し、RPNはS/O/Dが揃った場合のみ再計算。独立記録のExcel出力とFTAへの自動変換は未実装。再取り込み時には記録が追加されるため重複に注意。

## 木の管理・FTAの合流
「インポート」→「FTA JSONを選択」で、既存モデルを置き換えずに追加する。既定では独立した木。追加時に親を指定することもできる。
`trees` はルート事象の登録一覧。現在の計算対象ルートは従来どおり `top`。一つのモデル内で複数ルートを切り替えられ、登録ルートを他の木の子として接続しても別途表示できる。
取り込み時は内部IDを新規採番し、子参照・共通事象・グループ・FMEA手入力行・部品対応・重大度を一括で付け替える。既存事象との同名ID衝突で自動的に共通原因にしない。表示IDの衝突は `_I番号` で区別する。同じ物理原因なら、インポート後に既存事象へ明示的に接続し直す必要がある。評価期間の相違も警告する。
「木と接続」では、空の木の作成、既存事象のルート登録、木の表示、枝のJSON保存、接続追加・一つの親からの移動・接続だけの解除ができる。循環と重複接続を拒否し、最後の子を外した親が基本事象・確率0に変わる場合は確定前に警告する。事象や共有の下位原因は、切り離し・移動では削除しない。
枝のJSON出力は選択ルート以下と関連するFMEA・部品対応のみ。範囲外の行と独立取り込みFMEA記録は含まない。全体の保管には従来のJSON保存を使う。別ファイルの原本とのライブ参照・自動同期はしない。
インポート・接続操作はプレビュー作成時のモデル版を比較し、更新後の古いプレビューの適用を拒否する。反映は一括で行い、元に戻す操作に対応。
